**Branchement dans `page.tsx`.** Condition de rendu : `const navBlocs = user.role === 'ORGANISATEUR' && sejour?.createur?.id === user.id && !isDirect && !isEvenement`. Deux raffinements justifiés par rapport à la lettre du cadrage (`role === 'ORGANISATEUR' && !estAccompagnateur`) :
1. `sejour.createur.id === user.id` (créateur prouvé) au lieu de `!estAccompagnateur` : `estAccompagnateur` ne devient vrai qu'après le fetch async des accompagnateurs → un accompagnateur verrait la nav blocs pendant ~1 s (flash montrant Réservation/Budget qu'il n'a pas le droit de voir, vigilance §8.2 du cadrage). « Créateur prouvé » implique `!estAccompagnateur` (déf. page.tsx:93) et est stable dès le chargement du séjour. Un accompagnateur garde donc la barre actuelle du premier au dernier rendu.
2. `!isDirect && !isEvenement` : un organisateur créateur n'existe pas sur un DIRECT, et l'événementiel filtre la moitié des onglets (`ongletsVisibles`) — blocs quasi vides ; la barre actuelle y reste (conservateur, consigné en Écarts).

Quand `navBlocs` est faux, le JSX de la barre d'onglets (page.tsx:398-423) est rendu **strictement inchangé** (même JSX, même ordre, mêmes classes). `TABS`, keys, `ongletsVisibles`, `ONGLETS_TRACKING`, `ACCOMPAGNATEUR_TABS`, fallback `activeTab` : intacts.

**Blocs et répartition (cadrage §5.3).** Phase 1 « Je monte mon dossier » : Réservation = `[devis]` ; Pédagogie = `[projet]` (+ bandeau thématiques déplacé, voir plus bas) ; Budget = `[budget]`. Phase 2 « J'organise le séjour » : Inscriptions = `[participants]` ; Sur place = `[planning, groupes, chambres]`. Transverse : Échanges = `[messages, journal, documents]`. Les sous-onglets sont filtrés par `ongletsVisibles` (robustesse). Cliquer un bloc → `onSelectTab(premier onglet du bloc)` ; si le bloc actif a plusieurs onglets, une sous-barre reprend les libellés `TABS` existants. Le **contenu** reste rendu par `page.tsx` via `activeTab` — les sections de contenu et les `Tab*` ne bougent pas.

**États de bloc** (calculés sur des données déjà chargées) :
- Réservation : `budgetData.devis.statut` — SELECTIONNE/SIGNE_DIRECTION = fait ; EN_ATTENTE_VALIDATION = en cours ; EN_ATTENTE = à faire ; budgetData/devis null = neutre.
- Pédagogie : fait = `sejour.thematiquesPedagogiques.length > 0` (census finding 17 : seul critère persisté).
- Budget : fait = `Number(sejour.prix) > 0`.
- Inscriptions : 0 participant = à faire ; ≥1 non signé = en cours ; tous signés = fait. (Le raffinement par mode D14 arrive en SC4 ; ici critère générique sur `signeeAt`.)
- Sur place : pas d'état ; rendu atténué (« replié ») tant que 0 participant, normal ensuite.
- Échanges : pas de badge non-lus en v1 — `mes-non-lus` est un endpoint hébergeur (tracking `marquerVisite` est HEBERGEUR-only, census) et il faudrait un nouveau fetch ; consigné.

**Données participants.** Le compte des participants est nécessaire à l'emphase (D6) mais `loadParticipants` n'était appelé qu'à l'ouverture des onglets participants/groupes. Pour `navBlocs` uniquement, `loadParticipants()` est appelé au montage (fetch existant déclenché plus tôt, pas de nouvel endpoint — écart « sans nouveau fetch si possible » consigné, pas d'alternative).

**Emphase (D4+D6).** Premier bloc « à faire » dans l'ordre Réservation → Inscriptions → Budget → Pédagogie ; **sauf** si ≥ 1 participant : l'emphase passe en phase 2 (Inscriptions), la signature restant un rappel discret via le badge D7 du header. **Onglet par défaut** : un `useEffect` one-shot (ref `defaultAppliqué`) pose `setTab(ongletDuBlocEmphase)` dès que `budgetData` et le premier chargement participants sont résolus, uniquement si l'utilisateur n'a pas déjà cliqué — le `useState('devis')` et le fallback `activeTab` ne changent pas (les autres rôles gardent le comportement actuel).

**Bandeau thématiques.** Le JSX du bandeau (page.tsx:281-367) est extrait dans une variable locale `bandeauThematiques` (même JSX, un seul exemplaire) : rendu à sa position actuelle quand `!navBlocs` (accompagnateur et autres cas actuels du rôle ORGANISATEUR), rendu en tête de la section `projet` quand `navBlocs` (déplacement, pas duplication). **Badge D7/D8 (`SejourHeader`).** Nouvelle prop optionnelle `badgeEngagement?: { label: string; cls: string } | null`. `page.tsx` la calcule pour l'organisateur créateur uniquement : depuis `budgetData.devis.statut` (EN_ATTENTE → « En attente de signature » ambre ; EN_ATTENTE_VALIDATION → « En cours de validation direction » bleu ; SELECTIONNE/SIGNE_DIRECTION → « Séjour confirmé ✓ » vert ; NON_RETENU → « Annulé »), fallback `sejour.statut` (CONVENTION/SIGNE_DIRECTION → confirmé ; OPTION → en attente de signature) quand `budgetData` n'est pas encore chargé.
